> 筆者（青木 博資）がAI社員（Claude / Codex）と運営する一人会社KADOの実例です。AI社員が執筆し、筆者が事実確認と最終確認をしています。

**検証**：できあがった物が、条件や元の資料と合うかを確かめることです。  
**モデル**：ClaudeやCodexなど、AIの頭脳の種類や版です。

## 同じAIのセルフチェックだけでは、前提を疑いにくい

![セルフチェックと独立チェックの違い](/images/kado-x08-self-vs-independent.png)

同じ会話の中で「確認もして」と頼むと、誤字や単純なもれは見つけられます。ただし、作る時の思いこみまで同じため、前提のまちがいを「問題なし」としやすくなります。

KADOでは、作る人と疑う人を分けました。役名を増やすことではなく、作った時の先入観を切ることがねらいです。

- 検証役に、実行役との会話は渡さない
- 「セルフチェック済み」という説明も渡さない
- 渡すのは、完成したファイル・要件・照合資料だけ
- 品質をAI一体の注意深さではなく、仕事の流れで守る

## 3つの役を、4段階で動かす

![参謀、実行役、検証役で進める4段階](/images/kado-x08-four-step-flow.png)

1. **参謀**が、目的・成果物・制約・完了条件・担当AIを決める
2. **実行役**（作る役）が、作成や修正を行い、セルフチェックを返す
3. **検証役**（疑う役）が、成果物を独立して調べ、「合格」か「差し戻し」を返す
4. **参謀**が、結果を判定して最終報告する

参謀は品質に責任を持ちますが、長文やコードは作りません。計画・仕事を渡すこと・判定に集中し、自分の考えを自分で正しいことにしないためです。

### 差し戻しは、直せる形で返す

- 文章：`ファイル:行 | 問題 | 根拠 | 修正案`
- コード：上の4点に加えて、同じ問題を起こす手順
- 冒頭の答え：必ず「合格」か「差し戻し」
- 再確認：実行役が直し、同じ検証役がもう一度見る
- 終了条件：検証役の「合格」

「全体的に分かりにくい」だけでは直せません。場所と根拠を結びつけると、どの指摘をどう直したかも残せます。

## 別のAIを組み合わせる

| 役 | KADOでの置き方 | ねらい |
|---|---|---|
| 文章・コードの実行役 | Codex | 成果物を作る |
| 完成物の検証役 | Claude | 別の考え方で疑う |
| Claude側の呼び出し係 | 軽量モデル | `codex-companion` を一度呼び、標準出力を返す |
| 参謀 | 計画・仕事を渡すこと・判定に限定 | 二重作業を防ぐ |

実行役と検証役は、できるだけClaudeとCodexのような別系統にします。どちらが上かではなく、考え方のくせをずらし、片方の見落としをもう片方が拾うためです。

この執筆の流れでは、執筆や実装はCodexの高effort（時間をかけて考える設定）、完成物の検証はClaudeの標準モデルが担当します。呼び出し係まで作業すると、二重実行になり、責任と利用量が分かりにくくなります。

**標準出力**：実行した道具が、結果として画面へ返す文字です。

## 稟議の紙面で見つけた、3種類の問題

![稟議の紙面を三つの角度で調べる](/images/kado-x08-three-checks.png)

| 見つけた問題 | 確かめ方 |
|---|---|
| 数値の不一致 | 照合元を渡し、本文・比較表・集計の表示値を計算し直す |
| 機微情報の細かさ | 判断に必要か、分類を大まかにするか、伏せ字で足りるかを見る |
| 表の読みやすさ | 見出しと数値の関係、せまい画面のはみ出し、読み上げ時の比較軸を見る |

検証役は、好みの別案を出す人ではありません。要件と証拠をもとに、判断をまちがわせるずれを、直せる形で返します。

## 定額の利用枠に合わせて見直す

- 実行役と検証役の本体は、Codexの高effortへ寄せる
- Claude側の呼び出し係は、軽量モデルにする
- 参謀は、計画・仕事を渡すこと・判定だけを行う
- 毎月、実行回数・差し戻し率・見逃し・所要時間を記録する
- 別系統で確かめる原則を守れば、実行側は仕事ごとに変えてよい

相互チェックでは呼び出し回数が増えます。定額の利用枠と実際の使い心地を見ながら、置き方は固定せず見直します。

## 定義集を使う

定義集は GitHub で公開しています: https://github.com/t001ffinsta/cross-verify-agents

`cross-verify-agents` には、Claude Code用の定義が6本あります。

- 全体をまとめる `chief`
- 文章用の `exec-writing` と `verify-writing`
- コード用の `exec-code` と `verify-code`
- 指揮する人から独立した `auditor`
- README改訂を題材にした、計画・差し戻し・再確認・報告の例

### 導入の手順

1. `agents` 内のファイルを、対象プロジェクトの `.claude/agents/` へ置く
2. 実行役の定義にある `<codex-companion のパス>` を、自分の環境に合わせて置きかえる
3. 参謀に、対象ファイル・変更できる範囲・参照資料・完了条件を渡す
4. 検証役に、成果物と要件だけを新しい会話で読ませる
5. 必要なら、引用ルール・表記辞書・対応バージョン・安全の基準を確認項目へ足す
6. 「合格／差し戻し」と、行番号つきの指摘形式は残す

プラグインの場所や版は環境で変わるため、固定値にはしていません。

**プラグイン**：道具へ機能を後から足す部品です。

同じAIに二度うなずかせず、作る役と疑う役を分ける。小さな定義ファイルでも、AIとの制作は一回の生成から、記録の残る工程へ変わります。
